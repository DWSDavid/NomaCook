## 2. 数据流(实际代码路径)

```
MP4 (data/test_videos/)
  → harness/run_pipeline.py            [总装入口]
  → YOLO(步骤词表) + MediaPipe(帧时间戳) + fusion + HSV 颜色
  → server/pipeline/evidence.py        [感知 → EventEnvelope,确定性 ID/时钟]
  → server/events/EventLog             [幂等落盘 events.jsonl]
  → server/engine/StateEngine.consume  [单写者按 seq 消费,步骤推进]
  → 每 3s 关键帧: 原始 JPG + timeline.jsonl 状态对比 + VLM 门控触发
  → server/pipeline/render.py          [检测框+骨架+横幅+分数条 → annotated.mp4]
  → server/pipeline/narrate.py         [台词 → TTS → ffmpeg → annotated_narrated.mp4]
  → server/pipeline/report.py          [report.md 人读报告]
```

关键设计决定:
- **确定性契约**:帧时间 = frame_idx×1000/fps;t_server_est 挂固定 SESSION_EPOCH;
  event_id = evt_<session>_<seq>;回归一律 CPU。验收:两次运行 replay compare = `equal`
  (manager 亲测,含跨会话对比)。
- **脚本化证据注入(--script)**:SOP 权重刻意让纯感知(0.3)够不到阈值(0.7),
  必须叠 VLM(0.4)或口头确认(0.3);离线确定性跑通全 4 步靠脚本模拟,真实 VLM 走 --vlm。
- **关键帧即产品预演**:3-5s 采样间隔 = 未来 ESP32 端侧拍照上行周期;
  clean_sessions = "做完菜即删"策略;关键帧存原始帧(无标注)留给 VLM。

## 4. 一条命令的成品链(当前可用)

```bash
# 录制(或直接把视频放 data/test_videos/)
.venv/bin/python harness/record_clip.py --duration 90 --name my_cook

# 全功能:真实 YOLO+MediaPipe+颜色+真实 VLM+配音
set -a; source .env; set +a
.venv/bin/python harness/run_pipeline.py --source data/test_videos/my_cook.mp4 \
  --device mps --vlm gemini --narrate say

# 看完即删
.venv/bin/python harness/clean_sessions.py --keep 1
```
